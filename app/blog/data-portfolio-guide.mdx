# Building a data portfolio that actually gets noticed

Recruiters spend **7 seconds** on your portfolio.

## What doesn't work

- ❌ 20 Titanic survival tutorials
- ❌ Jupyter notebooks with no context
- ❌ Projects copied from Kaggle without adaptation
- ❌ Code that doesn't run

## What actually gets noticed

### 1. Three to five real projects

Not 20. Three to five, each well-documented and thoughtful.

### 2. A clear README for every project

Your README should answer:

- **What problem does this solve?**
- **What data did you use?**
- **What approach did you take?**
- **What were the results?**

### 3. Deployed demos

A Streamlit, Hugging Face Space, or Vercel deployment makes your project **clickable**.

### 4. A story, not a tool dump

Bad: "Used Python, pandas, scikit-learn."

Good: "Analyzed 50,000 customer records to predict churn. Discovered that customers with 2+ support calls in their first month had 4x higher churn rate."

## What recruiters actually check

1. **Does the code run?**
2. **Is the README clear?**
3. **Are there results?**
4. **Is there thought behind the choices?**

## Conclusion

Three great projects > twenty mediocre ones.
